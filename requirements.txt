# Everything that ends up inside the shipped app, pinned exactly.
#
# Pinned rather than floating because a build is not reproducible otherwise:
# two builds of the same commit a week apart were picking up different Flask,
# pywebview, pythonnet and yt-dlp versions, so "worked in the beta, broken in
# the release" could happen with no code change at all. These are the versions
# 1.2.4b was built and tested with.
#
# yt-dlp is pinned too, which is the opposite of the usual advice — and right
# here, because it is frozen into the exe. A user only ever gets a new yt-dlp
# by updating FinFetcher, so floating it at build time buys no freshness; it
# only means nobody can say which one a given user is running.
#
# The cost of pinning is that these go stale silently. BUMP THEM AS PART OF
# CUTTING A RELEASE, yt-dlp especially — YouTube breaks extractors constantly
# and a stale one is a broken app. To re-resolve the whole set:
#
#     python -m venv fresh && fresh/Scripts/pip install flask pywebview yt-dlp certifi mutagen
#     fresh/Scripts/pip freeze
#
# --- what the app imports directly -------------------------------------
flask==3.1.3
pywebview==6.2.1
yt-dlp==2026.8.19
# Not imported by main.pyw, but not optional either: without certifi, HTTPS
# verification falls back to the Windows store, which shipped an expired root
# and broke the in-app updater in 1.2.2. mutagen is what yt-dlp uses to embed
# cover art into opus/flac.
certifi==2026.7.22
mutagen==1.48.1
# The JavaScript that solves YouTube's signature challenges, run by whichever
# runtime JsRuntimeManager finds. Without this package yt-dlp fetches the
# script from GitHub at run time — works, but makes the first download depend
# on a fetch this pin makes deterministic.
yt-dlp-ejs==0.8.0
